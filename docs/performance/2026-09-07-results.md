## Status and requested update

The requested next update is clearer field and storage graphics: recognizable resource types, capacity and usage. This audit branch does not change the runtime, population cap, save format, game economy or deployment. The experimental graphics and staffing-frequency modification remain an isolated test workload, not an approved production patch.

The current supported housing maximum is 450 residents, independent of device power. Injected populations above 450 are workload probes with the original housing/job capacities, not playable or economically sustainable expansions.

## What was actually measured

39 complete scenario runs, 612.8 seconds of timed samples and 31,368 game callbacks. Additional evidence includes a paired frozen-state drawing microbenchmark and a functional test of a portable mobile performance page. Both original Node regression suites passed again, including the 450-resident food/housing/payroll audit and all ten militia-expedition test groups.

Environment: headless Chromium 144, Linux, Intel Xeon Platinum 8573C, software canvas/compositing. Phone-shaped viewport: 390 x 844 CSS pixels; actual game canvas: 780 x 1500. Tablet-shaped viewport: 1024 x 1366; canvas: 2048 x 2054. Storage was isolated and in memory. The mature fixture was synthetic. No private player save is published in this branch.

These are NOT physical iPhone, Galaxy, Pixel or iPad benchmarks. Host-relative CPU throttling does not emulate mobile GPU, storage, thermals or Safari. Physical-device maximum population, battery drain, sustained heat behavior, real storage latency and OS memory limits remain unmeasured.

## Strongest paired comparison

Same seeded 450-adult fixture, fixed camera, 60-second foreground samples, requested 10x. Experiment includes bounded extra field/store graphics and throttles only render-triggered staffing allocation to once per 250 ms; simulation/event allocation calls remain immediate.

| Metric | Current | Experiment |
|---|---:|---:|
| Callback cadence | 53.3 fps | 57.1 fps |
| Mean game callback work | 6.33 ms | 3.38 ms |
| p95 game callback work | 9.8 ms | 6.1 ms |
| p99 game callback work | 21.9 ms | 11.6 ms |
| p95 frame interval | 33.3 ms | 16.8 ms |
| Effective simulation speed | 9.64x | 9.88x |
| Frames longer than 50 ms | 44 | 10 |
| Long tasks | 50 | 11 |

Mean callback work fell 46.5%, and p95 work fell 37.8%. This is CPU-side headroom in one paired host experiment, not twice the display frame rate or an equivalent gain promised on every phone.

The colonist draw function recalculates staffing every rendered frame, occupying roughly half the measured game work in one profile. DO NOT SHIP THE TIMER SHORTCUT AS IS: drawing currently mutates game staffing. A production fix must make drawing read-only and recompute on explicit population, construction, payroll, inventory, equipment and policy invalidations. Verify deterministic gameplay/economic equivalence; regression success on the untouched release does not validate the experimental optimization.

One early graphics-only run was unfavorable: 45.7 fps and 17.8 ms p95. Seeded repeats returned 57.3-57.6 fps and 8.0-8.9 ms. The unfavorable run is retained. Frozen-state paired drawing medians were both about 5.39 ms: no stable small incremental cost was resolved, not proof that graphics are free.

The pilot allowed automatic camera recentering; later comparisons fixed the camera. Interrupted uncontrolled runs are retained but excluded from the 39-run summary. Shared-host noise, software rendering and short sessions limit inference. All raw samples and case definitions are preserved privately with the report.

## Speed, memory and graphical limits

The loop multiplies elapsed simulation time, rather than drawing ten times per frame. It clips frame deltas above 50 ms: under overload a displayed 10x can advance the colony slower than 10x. Include effective simulation speed, not just fps, in every release gate.

Canvas DPR is capped at two. One phone-sized RGBA buffer is about 4.46 MiB; the tested tablet-shaped buffer is 16.05 MiB. A full 14000 x 9000 world bitmap is about 480.7 MiB at DPR1 and 1.88 GiB at DPR2: do not use that caching design. JS-heap snapshots of 4.35-11.34 MiB are not total browser/GPU memory or a safe phone-RAM limit.

## Common mobile devices: provisional validation priorities

These are low-confidence engineering expectations, not measured device capacities. Hardware specifications establish identities only.

- Galaxy A16 5G Brazil/Exynos 1330: highest-risk reference group; test 300 and 450 at 10x before enabling richer default art or expansion.
- Galaxy A36/Snapdragon 6 Gen 3: test-first 450 floor, tightly bounded art; investigate 600 only after optimization.
- Galaxy A56/Exynos 1580 and Pixel 9a/Tensor G4: current 450 with restrained 2D improvements is a reasonable hypothesis; validate 600 then a separate 900 stage.
- iPhone 13/A15: 450 is a reasonable hypothesis; validate Safari, aging-battery and heat behavior before 600/900 stages.
- iPhone 15 Pro/A17 Pro, iPhone 16/A18, iPhone 17/A19 and Galaxy S25/Snapdragon 8 Elite for Galaxy: favorable expectations for current 450 and bounded art; 900 is a useful optimized-engine research checkpoint. 1350 is later research, not an approved limit.

No precise physical-device maximum is defensible yet. Preserve a 450-resident compatibility target while validating any larger simulation options.

## Recommended next implementation

1. Establish read-only rendering and correctly invalidated staffing snapshots; verify economic equivalence.
2. Deliver the small field/storage clarity update: 16-24 representative symbols per field, actual staff/slot labels, capped store gauges and current upgraded capacities. Start with a proposed 0.5 ms p95 added-art allowance after optimization, rather than consuming all measured reserve.
3. Refresh detailed statistics on demand or about 2-4 times per second; avoid one object per inventory unit, full-world textures, per-object blur or unbounded effects.
4. Test 600, then 900 residents with actual extra housing, jobs and logistics, separately from map and graphics changes. Test 100-200 additional simple animations before attempting the 500-circle workload.
5. Use a 60-fps-oriented physical-device acceptance target, game-work p95 <=8 ms, effective foreground 10x >=9.8x, no perceptible recurring stalls, and a 15-minute normal-play soak. Test pan/pinch, inspections, hunts, construction, cold routes, autosave, save import/export and thermal conditions. These are proposed gates, not current certifications.
